# Environment Variables Setup Guide

This guide explains how to configure environment variables for the Farmer Data Collection platform.

---

## Overview

The platform uses environment variables for:
- **API keys** - External service credentials
- **Database connections** - PostgreSQL, Redis
- **Feature toggles** - Enable/disable features
- **Security settings** - JWT secrets, encryption keys
- **Service URLs** - ML services, payment gateways

---

## Required Environment Variables

### Core Configuration

**DATABASE_URL** (Required)
- PostgreSQL connection string
- Format: `postgresql://username:password@host:port/database`
- Example: `postgresql://farmer_admin:password@localhost:5432/farmer_data_collection`
- See: `docs/POSTGRESQL_SETUP.md`

**JWT_SECRET** (Required - Already Configured)
- Secret key for JWT token signing
- Auto-generated by platform
- Do not modify unless necessary

---

## Weather Integration

**OPENWEATHER_API_KEY** (Required for Weather Features)
- OpenWeatherMap API key
- Get free key at: https://openweathermap.org/api
- Free tier: 60 calls/minute, 1,000,000 calls/month
- See: `docs/OPENWEATHERMAP_SETUP.md`

**To add:**
1. Register at OpenWeatherMap
2. Copy your API key
3. Go to Settings → Secrets in Management UI
4. Add new secret: `OPENWEATHER_API_KEY`
5. Paste your API key

---

## Google Maps Integration

**GOOGLE_MAPS_API_KEY** (Required for Mapping Features)
- Google Maps JavaScript API key
- Get key at: https://console.cloud.google.com/google/maps-apis
- Enable: Maps JavaScript API, Places API, Geocoding API

**Note:** The platform uses Manus proxy for Google Maps, so you may not need your own API key for basic features.

## How to Add Environment Variables

### Method 1: Management UI (Recommended)

1. Open Management UI (right panel)
2. Navigate to **Settings → Secrets**
3. Click **Add Secret**
4. Enter key name (e.g., `OPENWEATHER_API_KEY`)
5. Enter value
6. Click **Save**

### Method 2: Local Development

For local development, you can create a `.env` file:

```bash
# Create .env file
touch .env

# Add variables
echo "OPENWEATHER_API_KEY=your_key_here" >> .env
echo "DATABASE_URL=postgresql://..." >> .env
```

**Important:** Never commit `.env` to version control!

## Verification

### Check Environment Variables

**In Development:**
```bash
# Print all environment variables
printenv | grep -E "(DATABASE|OPENWEATHER|AFRICASTALKING)"
```

**In Application:**
```typescript
// Check if variable is set
console.log('OpenWeather API Key:', process.env.OPENWEATHER_API_KEY ? 'Set' : 'Not set');
console.log('Database URL:', process.env.DATABASE_URL ? 'Set' : 'Not set');
```

curl "https://api.openweathermap.org/data/2.5/weather?q=Lagos&appid=YOUR_API_KEY"

## Security Best Practices

### 1. Never Commit Secrets
- Add `.env` to `.gitignore` (already done)
- Use environment variables, not hardcoded values
- Rotate keys regularly

### 2. Use Different Keys for Environments
- Development: Test/sandbox keys
- Staging: Separate test keys
- Production: Production keys only

### 3. Restrict API Key Permissions
- OpenWeatherMap: Limit to specific APIs
- Stripe: Use restricted keys when possible
- Africa's Talking: Set IP whitelist

### 4. Monitor Usage
- Check API usage dashboards
- Set up alerts for unusual activity
- Review logs regularly

## Troubleshooting

### "Environment variable not found"
- **Solution:** Add variable via Management UI or `.env` file
- Restart development server after adding

### "Invalid API key"
- **Solution:** Verify key is correct, check for extra spaces
- Some keys take time to activate (e.g., OpenWeatherMap: 2 hours)

### "Connection refused"
- **Solution:** Check service is running (PostgreSQL, Redis)
- Verify connection string format

### Changes not taking effect
- **Solution:** Restart development server
- Clear browser cache
- Check if variable is actually set: `printenv | grep VARIABLE_NAME`
